# Contributing to Veltra Track

Thank you for your interest in contributing to **Veltra Track**! We welcome bug reports, feature requests, documentation improvements, and code contributions.

## Principles

1. **Zero-Dependency Core**: Veltra Track is intentionally designed as a lightweight, framework-free, zero-build application. We prioritize vanilla HTML, modern CSS, and pure JavaScript.
2. **Local-First & Privacy Always**: User data must never leave the user's browser without explicit manual export. No tracking scripts, third-party analytics, or surveillance telemetry.
3. **Accessibility & Delight**: Fast load times, responsive touch targets, dark/light theme fidelity, and smooth micro-interactions.

## How to Contribute

### Reporting Bugs
- Check the [GitHub Issues](https://github.com/TejaPriyan/Veltra-Track/issues) to ensure the bug hasn't already been reported.
- Open a new issue with clear reproduction steps, browser/OS version, and screenshots if applicable.

### Suggesting Enhancements
- Feature requests can be submitted via [GitHub Discussions](https://github.com/TejaPriyan/Veltra-Track/discussions) or Issues.
- Clearly describe the problem your enhancement solves and how it aligns with the local-first philosophy.

### Pull Requests
1. Fork the repository.
2. Create a descriptive feature branch: `git checkout -b feature/my-enhancement`.
3. Test your changes locally across desktop and mobile screen sizes.
4. Commit your changes with clear commit messages: `git commit -m "Add: support for custom sound chime"`.
5. Push your branch to GitHub and open a Pull Request against `main`.

## Code Guidelines
- Keep CSS variables unified with our design tokens in `:root`.
- Write semantic HTML5 and ensure accessible ARIA roles and labels.
- Verify that keyboard navigation (`Ctrl+K`, `Escape`, arrow keys) functions properly.
